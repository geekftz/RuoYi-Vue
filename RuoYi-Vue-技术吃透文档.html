★ 权限热刷新核心代码（TokenService.refreshPermissionByRoleId）
public void refreshPermissionByRoleId(Long roleId, SysPermissionService permissionService) {
    // 1. 扫描 Redis 中所有在线 Token
    Collection<String> keys = redisCache.keys("login_tokens:*");
    for (String key : keys) {
        LoginUser loginUser = redisCache.getCacheObject(key);
        // 2. 跳过管理员（拥有所有权限）
        if (loginUser.getUser().isAdmin()) continue;
        // 3. 判断用户是否拥有被修改的角色
        boolean hasRole = loginUser.getUser().getRoles().stream()
            .anyMatch(r -> roleId.equals(r.getRoleId()));
        if (!hasRole) continue;
        // 4. 重新查询权限并刷新 Redis 缓存
        loginUser.setPermissions(permissionService.getMenuPermission(loginUser.getUser()));
        refreshToken(loginUser);
    }
}

调用时机：SysRoleController.edit() 方法中，角色修改成功后立即调用。

6核心权限体系底层原理

6.1 完整登录流程

1. 前端：用户输入 用户名 + 密码 + 验证码 2. POST /login { username, password, code, uuid } 3. SysLoginService.login() ├── validateCaptcha(): Redis 取验证码对比后删除 ├── loginPreCheck(): 长度校验 + IP 黑名单 └── authenticate() └── UserDetailsServiceImpl.loadUserByUsername() ├── 查数据库用户 ├── 检查状态（删除/停用） └── SysPasswordService.validate() ├── Redis 取错误次数（超 5 次锁 10 分钟） └── BCrypt.matches(原始密码, 数据库密码) 4. tokenService.createToken(loginUser) ├── 生成 UUID 作为 Token 标识 ├── setUserAgent(): 设置 IP/浏览器/OS └── refreshToken(): 存入 Redis（30 分钟 TTL） 5. 返回 { code: 200, token: "eyJhbG..." } 6. 前端 setToken() → Cookie + Vuex

6.2 请求鉴权链路

# 每个 HTTP 请求 JwtAuthenticationTokenFilter.doFilterInternal() ├── tokenService.getLoginUser(request) │ ├── Header 取 Authorization: Bearer xxx │ ├── 解析 JWT → UUID │ └── Redis 取 LoginUser ├── tokenService.verifyToken(loginUser) │ └── 距过期不足 20 分钟 → refreshToken() 自动续期 └── SecurityContextHolder.setAuthentication() ↓ Controller: @PreAuthorize("@ss.hasPermi('xxx')") ├── PermissionService.hasPermi() │ └── 检查 loginUser.getPermissions() 是否包含权限 └── 方法执行

6.3 三层权限完整源码

第一层：菜单权限（路由级）

后端 getRouters() 按角色查询有权限的菜单树；前端路由守卫动态注册路由，无权限菜单不出现。

第二层：按钮权限（操作级）

# 后端 @PreAuthorize("@ss.hasPermi('system:user:add')") # 前端 <el-button v-hasPermi="['system:user:add']"> # 后端 PermissionService.hasPermi() loginUser.getPermissions().contains(permission) ├── 包含 "*:*:*" → 超级权限 └── 包含指定权限 → 返回 true

第三层：数据范围权限（数据级）

data_scope含义SQL 条件
1全部数据不加条件
2自定义d.dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ?)
3本部门d.dept_id = 用户部门ID
4本部门及以下d.dept_id IN (SELECT ... WHERE find_in_set(?, ancestors))
5仅本人u.user_id = 当前用户ID

6.4 角色权限变更后实时刷新（关键新增逻辑）

★ 完整实现链路
管理员修改角色权限 ↓ SysRoleController.edit() ├── roleService.updateRole(role) → 更新 sys_role + sys_role_menu └── tokenService.refreshPermissionByRoleId(roleId, permissionService) ├── 遍历 Redis 所有 login_tokens:* Key ├── 跳过管理员 ├── 判断用户是否拥有该角色 ├── 重新查询权限 → loginUser.setPermissions(newPermissions) └── refreshToken(loginUser) → 重新写入 Redis ↓ 在线用户下次请求自动使用新权限，无需重新登录
补充机制：getInfo 接口也有权限刷新逻辑——如果当前用户的权限集合与数据库最新权限不一致，自动刷新 Redis 缓存。这确保即使用户的 Token 未被角色变更触发刷新，下次调用 getInfo 时也会自动同步。

9安全专项

9.1 文件上传安全：后缀白名单拦截 html 等危险文件

★ 白名单制：只允许指定类型，html/htm/js/jsp/php 均被拦截
// MimeTypeUtils.java - 白名单定义
public static final String[] DEFAULT_ALLOWED_EXTENSION = {
    "bmp", "gif", "jpg", "jpeg", "png",        // 图片
    "doc", "docx", "xls", "xlsx", "ppt", "pptx", "txt",  // 文档
    "rar", "zip", "gz", "bz2",                 // 压缩文件
    "mp4", "avi", "rmvb",                      // 视频
    "pdf"                                      // PDF
};
// 注意：不包含 html, htm, js, jsp, php, sh, bat 等危险类型

校验流程（FileUploadUtils.assertAllowed）：

  1. 文件大小校验（默认 50MB）
  2. 获取文件后缀（先取文件名后缀，取不到则从 ContentType 推断）
  3. 白名单校验：isAllowedExtension(extension, allowedExtension)
  4. 不在白名单 → 抛出 InvalidExtensionException

文件下载安全（FileUtils.checkAllowDownload）：

  • 禁止目录跳转：if (contains(resource, "..")) → false
  • 仅允许白名单后缀下载

9.2 用户密码安全：自定义密码复杂度配置

chrtype规则正则表达式
0（默认）任意字符（排除危险符号）/^[^<>"'\|\\]+$/
1纯数字/^[0-9]+$/
2纯字母/^[a-zA-Z]+$/
3字母+数字（必须同时包含）/^(?=.*[a-zA-Z])(?=.*[0-9])[a-zA-Z0-9]+$/
4字母+数字+特殊字符/^(?=.*[A-Za-z])(?=.*\d)(?=.*[~!@#$%^&*()\-=_+])[...]+$/

后端传递到前端：getInfo() 接口返回 pwdChrtype，前端存入 sessionStorage，passwordRule.js mixin 根据 chrtype 动态生成校验规则。

密码过期策略：

  • initPasswordModify=1：未修改初始密码时登录提醒
  • passwordValidateDays>0：超过天数登录提醒修改

密码错误锁定：最大 5 次，锁定 10 分钟（Redis pwd_err_cnt:{username} 计数）

9.3 在线用户权限热更新缓存机制

无需用户重新登录，权限变更实时生效
  1. 管理员修改角色权限（菜单分配）
  2. SysRoleController.edit() 调用 refreshPermissionByRoleId()
  3. 遍历 Redis 所有 login_tokens:* Key
  4. 跳过管理员、检查角色匹配、重新查询权限
  5. 更新 loginUser.setPermissions() → 重新写入 Redis
  6. 用户下次请求自动使用新权限
